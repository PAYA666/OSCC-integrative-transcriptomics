# Running the analyses

## Workspace and environment

Use the source tree as a reference and execute in a separate writable workspace. Set absolute paths before running scripts:

```powershell
$env:OSCC_PROJECT_ROOT = "D:/your-work/processed-project"
$env:OSCC_DATA = "D:/your-work/processed-project"
$env:OSCC_REVISION = "D:/your-work/revision"
```

`OSCC_PROJECT_ROOT`/`OSCC_DATA` refer to the processed project layout generated by the historical stages, not an arbitrary folder of raw GEO files. `OSCC_REVISION` refers to a writable copy of the numbered revision directories, including generated inputs/results. Preserve relative directory names. A repository clone alone does not provide the original large intermediate objects.

Historical stages are ordered in historical_run_order.tsv. Part 1 supplies expression/clinical objects and frozen scoring inputs; Part 2 supplies smoking-related analyses; Part 3 supplies resistance and temporal single-cell analyses. Do not run every historical script indiscriminately: alternative and supplementary stages are listed separately. The reconstructed Part 3 convergence candidate requires particular attention to its inputs.

## Strict nested pipeline

1. Create the processed count matrix, clinical annotations and frozen project objects required by the scripts. `revision/01_baseline/audit.R` reads them to generate the sample manifest and original fold map in `01_baseline/results/`.
2. From `revision/02_strict_cv/`, use `Rscript run.R 1 100` to fit the specified 100 outer models. This is a long analysis, not an upload check. The scripts skip matching checkpoints and verify their signatures; do not overwrite or mix checkpoints from different input versions.
3. Run `summarize.R`, `summarize_feature_frequency.R`, and the relevant clinical/permutation/half-sample analyses after their prerequisite outputs exist. Run scripts from their own numbered directory unless they explicitly set a workspace.
4. Evaluate external cohorts in their respective directories. Clinical and pathway sensitivities similarly require the corresponding processed objects and annotations.

The original processed TCGA file names expected by the baseline/pipeline include `TCGA_OSCC_Nature8_raw_count_matrix.rds` and `TCGA_OSCC_Nature8_metadata.tsv`. They are not bundled. Other literal input names can be read directly from the stage code; earlier stages and source data must be supplied rather than replacing missing inputs with fabricated objects.

## Frozen Final8 scoring

```r
source("revision/12_single_sample/score_final8.R")
reference <- read.delim("parameters/TCGA_reference.tsv")
```

Call `score_final8(x, reference, expression_scale="TCGA_Nature8_VST")` only when the named eight-gene vector `x` is already on the archived TCGA expression scale. This function computes a continuous score, not a calibrated survival probability or cross-platform normalization. External-array validation uses cohort-specific processing documented in the manuscript and external-cohort scripts.

## Targeted Python analyses

The staged GSE84846 script accepts `--matrix`, `--reference` and `--output-dir`. Give `parameters/TCGA_reference.tsv` explicitly as `--reference`. Outputs can include patient-level scores: keep those local rather than adding them to this public results tree.

The SEQC bridge script accepts input/output directories and a reference table; consult its `--help`. The weighted-profile script expects `SEQC_Final8_reference_expression_long.tsv` in its working source directory and `TCGA_reference.tsv` in the sibling `12_single_sample/` directory. Copy these two small frozen tables from `results/R2_Major2_SEQC_bridge/` and `parameters/` into a separate analysis workspace before running it.

Historical Part 1 exact versions are not fully recorded; do not infer them from later sessions.

Python scripts use the standard library, with PyMuPDF/Pillow for figure-related utilities and other imports shown in their source. No environment or dependency file is represented as tested unless it was actually tested. Install prerequisites separately; some historical sources include package-installation calls. No analysis was executed automatically during the public-file packaging pass.
